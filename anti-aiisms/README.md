# Marp Anti-AI-isms

Marp スライドから「AI 臭」を抜くための知識ベース。

## このディレクトリの目的

語彙ブラックリスト（「深掘り」「次アクション」など単語の置換）では追いきれない、文体・文構造・章名の癖といった**構造レベルの違和感**を、ルール（rubric）と実物の文体例（corpus）の 2 つで管理する。

git 管理されているため、`git diff` で追加・変更履歴を確認できる。

## ファイル構成

| ファイル | 役割 | 育て方 |
|---|---|---|
| [RUBRIC.md](RUBRIC.md) | 構造ルール R1〜Rn の一覧 | 新しい AI 臭パターンに気づいたら行追加 |
| [CORPUS.md](CORPUS.md) | 参照資料の manifest（承認済資料へのポインタ） | 承認された資料が出るたびに行追加 |
| [CHANGELOG.md](CHANGELOG.md) | 追加・変更履歴（[rubric] / [corpus] / [infra] タグ） | 上の 2 つを変更したら 1 行追加 |
| README.md（本ファイル） | 全体の入り口 | 構造が変わったら更新 |

## 使い方

### 自動監査ツールから参照する

3 LLM（Codex CLI / Gemini CLI / Claude subagent 等）による独立合議で AI 臭を判定する skill / script に `RUBRIC.md` と `CORPUS.md` を読み込ませて使う。判定結果からルール／コーパスを増やしていく成長サイクルで運用する。

呼び出された時点で `RUBRIC.md` と `CORPUS.md` を Read し、新規スライドに対して 3 系統で判定。`CORPUS.md` に追加した資料は次回呼出時から参照対象に含まれる。

### データフロー

```
スライド.md  ──┐
                ├──► 3 LLM 並列判定 ──► サマリ + Diff
RUBRIC.md   ───┤                          │
CORPUS.md   ───┘                          ▼
                          ユーザー承認（3 段独立）→ Edit 適用
                                            │
                                            ▼
                            （承認時のみ）CORPUS.md / RUBRIC.md 更新 + git add
```

### 手動参照

人間が直接読んで自己点検にも使える。特に RUBRIC.md の R1〜Rn は社外配布資料を書くときの自己チェックリストとして有用。

## 育て方（成長サイクル）

### 1. 新しい AI 臭パターンを見つけたら

```
1. 監査ツールでルール候補を提示してもらう（3 LLM 独立評価）
2. 2 者以上が指摘するパターンのみ採用（単独指摘は採用しない）
3. RUBRIC.md の表に行追加（R<次の番号>、追加日・根拠ログパス必須）
4. CHANGELOG.md に `[rubric] R<N> 追加: <ルール本文>` を 1 行記録
5. git commit
```

### 2. 承認された参照資料が増えたら

```
1. その資料の絶対パスを確認（コーパスにコピーは不要、参照のみ）
2. CORPUS.md の表に行追加（クライアント名・状態を明記）
3. CHANGELOG.md に `[corpus] <client> <type> 追加: <絶対パス>` を 1 行記録
4. git commit
```

### 3. 過去に却下された資料があれば

```
状態列を「反面教師」にして CORPUS.md に追加。
「これに似ないこと」の参照として使われる。
```

## 設計思想

- **語彙ではなく構造**：「ドリル → 分析」の単語置換ではなく、「章名に比喩を使わない」の構造ルール
- **コーパスで地続き**：承認済資料が増えるほど判定基準が「実物の文体」に寄っていく
- **3 LLM 独立合議**：単一モデルのバイアスを除く
- **ユーザー承認を必ず挟む**：自動編集ではなく Diff 提示 → 承認 → 適用
- **git 管理で透明**：何が・いつ・なぜ追加されたかが追跡できる
