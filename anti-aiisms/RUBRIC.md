# Marp AI 臭防止ルーブリック

Marp スライド（特に社外配布の業務報告資料）で AI 臭を避けるための構造的ルール。

**目的**: 語彙ブラックリスト方式ではなく、文体・構造の原則として運用。

## ルーブリック R1〜R10

| # | ルール | 違反するとなぜ AI 臭か | 対象範囲 | 根拠 |
|---|---|---|---|---|
| R1 | 章名・見出しに比喩／カタカナ抽象語を持ち込まない（ドリル/ カルテ/ タイムライン/ 集中型 等） | コンサル翻訳調、3 LLM が一致して指摘 | H1〜H3 見出し | cross-check 3 者一致 |
| R2 | 「A ではなく B」の対比断定を社外資料で使わない（相手側設備に対して特に） | 断定の鋭さが提案者として強すぎる | 本文全体 | cross-check Codex+Gemini |
| R3 | 矢印（→）で因果や時系列を表現しない | フローチャートをスライド本文に押し込んだ見た目 | 本文・表セル | cross-check 3 者一致 |
| R4 | 「ねらい」「主張」「結論」など直訳調の見出しを反復しない（章末で揃えすぎ） | "Objectives"/"Key messages" の機械的翻訳 | H3 サブ見出し | cross-check Claude |
| R5 | **太字累積の禁止**：第一閾値＝1 スライド内に `**...**` が **4 個以上**で違反（種別問わず）。第二閾値＝2〜3 個でも「結論文（述語を含む節）」と「数値・固有名」の **両カテゴリが混在** すれば違反 | 累積過多で読み手の優先度判断を奪う | **本文の `**...**` のみ**。タイトル（H1/H2）・表ヘッダ・コードブロックは除外 | cross-check 3 者一致 + W チェック |
| R6 | 2〜3 例しかないデータで「再現性」「パターン」と抽象化しない | サンプル数に対して抽象度が高すぎ | 本文全体 | cross-check Codex |
| R7 | 内部ラベル／システムコードを本文に並べず注釈に逃がす | 社外読者にとってのノイズ | 本文（脚注・コードブロックは除外） | cross-check Claude |
| R8 | **体言止めとです/ますの混在禁止**：本文文末に「です/ます終止」と「体言止め」が **両方 1 個以上ずつ**存在で違反。**明示的に非違反**：全文末が「常体のみ」「です/ますのみ」「体言止めのみ」のいずれかで揃っている場合 | 文末の不揃いが目に付く | **本文の文末トークン**。タイトル・短ラベル・表セル・箇条書き先頭は除外 | cross-check Gemini+Claude + W チェック |
| R9 | **見出し副題の「の」連鎖禁止**：助詞「の」が **3 個以上**、または **名詞句連結が 4 つ以上**で違反（OR 条件） | 機械生成タイトルの典型 | **H1/H2 行 + スライド冒頭のリード 1 文**。助詞の「の」のみカウント（「もの」「こと」内部・固有名詞・引用内は除外） | cross-check Claude + W チェック |
| R10 | 相手側の対応を責める含意のある表現を避け、前向きな提案形にする | 協力関係を損なう | 本文全体 | cross-check Gemini |

## 読者プロファイル別の調整メモ（例）

ルーブリック R1〜R10 の上に、読者プロファイルごとの追加メモを置く。以下は例で、実際の運用ではプロジェクトに応じて差し替える:

- **業務報告／現場運用部門向け**：カタカナ抽象語が特に浮く。「内訳」「掘り下げ」「個別状況」など和語／漢語へ
- **役職者も読む社外資料**：略語の初出定義を強めに、本文中の連発は控えめに
- **丁寧形を強めたい社外資料**：「ご報告」「ご相談」「ご確認」など見出しレベルでの丁寧形

具体的なクライアント別メモは [CORPUS.md](CORPUS.md) のクライアント別のメモ節に記録する。

## ルールの育て方

新しい AI 臭パターンに気づいたら：

1. 3 LLM 独立評価で 2 者以上が指摘するか確認
2. 指摘内容を**構造ルール**として表現（語彙ではなく「〜という構造を避ける」形）
3. 上の表に行を追加（次の番号 R11, R12...）
4. `CHANGELOG.md` に追加理由と日付を記録
5. `git commit -m "rubric: add R11 ..."` で履歴を残す

## ルール削除・修正の判断

- ルール違反指摘が「3 LLM すべてで一度も再現しない」状態が 3 回連続でカウントされたら、廃止候補
- 別ルールに統合可能なら統合（番号は欠番に。再利用しない）
- 修正履歴は `CHANGELOG.md` に必ず記す
